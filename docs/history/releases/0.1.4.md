# mottainai 0.1.4

## Summary

Semantic workflow and CI-hardening release. Builds on 0.1.3's workflow-task
engine with the derived-fact layer promised by Issue #34's family: a
TypeScript semantic fact extractor, Symbol-level effect/policy conformance
analysis, an explicit semantic mutation boundary, a reconciliation/doctor
audit surface, and a runtime build-identity domain object. Alongside the
workflow engine, this release closes the Managed Hooks security gate,
lands CI critical-path and dual-LLM review budget work, and adds CodeQL
and mutation/property test-effectiveness coverage.

## Highlights

- **TypeScript semantic fact extractor** (#118): TypeChecker-authority
  fact provider mapping into the canonical semantic IR, with fixtures and
  determinism/unknown-state/ID-stability tests.
- **Symbol effects and policy conformance** (#133): deterministic
  Symbol-level effect analysis derived from TypeChecker-resolved
  identities, propagated through the Symbol call graph, evaluated against
  declared policies, and preserving evidence/provenance/incomplete-analysis
  state.
- **Semantic mutation API** (#138, closes #49): single explicit
  planning/binding/validation/persistence boundary for semantic writes.
  Plans and source writes are deterministic, bound to current Symbol
  identity, and fail closed on tampered, stale, missing, or ambiguous
  state.
- **Semantic verification adequacy model** (#114): repository semantic IR
  model for verification requirements, perspectives, evidence, and
  deterministic adequacy summaries.
- **Reconciliation doctor audit and export** (#129, Issue #38): compares
  recorded SQLite workflow state against bounded Git/provider
  observations, records privacy-safe guardrail audit decisions, and emits
  a versioned redacted JSON state export.
- **Live repository model for the Semantic Project Viewer** (#131):
  replaces fixture data with a deterministic live compiler/provider over
  the #118/#84 facts, preserving the existing `RepositorySemanticQuery`
  contract.
- **Safe task cleanup and crash recovery** (#115, Issue #37): two-stage
  cleanup that plans serializably, revalidates immediately before each
  external mutation, and commits state only after verification.
- **Managed Hooks review gate** (#134): first Managed Hooks vertical
  slice — a transport-independent `HookEvent`/`HookDecision` path shared
  by the Claude Code and Codex client adapters, with capability-based
  anti-bypass, bounded agent-visible output, and install/status/doctor/
  repair/uninstall/explain lifecycle management.
- **Runtime build identity** (#117): one canonical, versioned runtime/
  build identity object; doctor, runtime-status, and early-startup
  diagnostics derive from it, and packed artifacts carry build-time
  metadata so identity no longer depends on a live Git checkout.
- **Path-aware governance gates** (#116, Issue #26): path-aware governance
  evidence gates, safe regression-proof planning, report-only rollout
  observations.
- **Fault-injection test boundaries** (#130, closes #23): deterministic
  fault-injection coverage for the workflow domain.
- **Mutation and property test effectiveness** (#128, Issue #24): bounded
  property-based invariant checks, a targeted mutation catalog and
  sandbox runner, a committed baseline report, and a manual/weekly CI
  workflow with machine-readable artifacts.
- **CI critical path under two minutes** (#142, closes #139): reduces PR
  CI feedback latency while retaining the full validation contract.
- **Dual LLM review budgets** (#136, closes #119): PR-Agent keeps its
  enforceable input-token limit; OpenCodeReview stays disabled by default
  until its downstream request limit is enforceable and
  regression-tested.
- **OpenCodeReview parallel evaluation** (#112): isolated
  `open-code-review.yml` workflow running Alibaba OpenCodeReview alongside
  PR-Agent; workflow skeleton only, credentialed job stays disabled by
  default pending context-budget verification.
- **CodeQL advanced analysis** (#137): repository-owned CodeQL setup for
  JavaScript/TypeScript and GitHub Actions with the `security-extended`
  suite, on PRs to `main`, pushes to `main`, and a weekly scan.
- **AGENTS.md execution contract** (#121): replaces `AGENTS.md` with a
  minimal 9-section execution-discipline contract; strengthens the
  `CLAUDE.md` pointer so it is read as a required precondition before
  work starts.

## Fixed

- Managed hook runtime review gate closed against bypass paths (#134).
- Runtime diagnostic identity/redaction: development `git_sha` now
  derives from the entry point's own package root instead of `cwd`,
  preventing an unrelated consumer checkout's commit hash from leaking;
  common standalone credential shapes (`sk-proj-`, `ghp_`, `github_pat_`,
  `xoxb-`, etc.) are now recognized in `sanitizeUpstreamError`.
- `assessmentFor()` no longer lets stale historical `failed` evidence
  permanently block a requirement after a newer passing verification is
  recorded; failed-precedence is scoped to current evidence, with
  regression coverage for both recovery and still-blocking cases.
- E2E missing-config assertion updated to match the runtime diagnostic
  stderr block instead of asserting exact equality against
  environment-varying fields.
- Runtime identity tests made environment-independent.
- OpenCodeReview trigger/routing: `ready_for_review` added to the
  `pull_request` trigger so a draft marked ready without a new commit
  still gets reviewed; `route_categories` dropped since it ORs with
  `route_severity_below`, which could misroute high/critical findings to
  the summary instead of inline.

## Behavioral changes

- None of the changes in this release alter existing CLI, configuration,
  or package entry-point contracts; all workflow/semantic additions are
  additive to the existing model (see per-PR "Breaking changes: No"
  above each Highlight's linked change).

## Upgrade instructions

```bash
npx -y mottainai@0.1.4 init --yes --no-register
```

or, for an interactive setup:

```bash
npx -y mottainai@0.1.4 init
```

No configuration migration is required from 0.1.3.

## Breaking changes

None.

## Known limitations

- Managed Hooks review gate ships its first vertical slice only; broader
  hook coverage remains tracked separately.
- OpenCodeReview stays disabled by default pending downstream
  request-limit enforcement and regression testing (#136); the parallel
  evaluation workflow (#112) is skeleton-only until then.
- Workflow-task tools remain observation/dogfooding only: no commit,
  push, PR, or cleanup enforcement is wired to them yet (carried over
  from 0.1.3).
