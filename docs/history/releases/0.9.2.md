# Mottainai 0.9.2

Mottainai 0.9.2 is a release-infrastructure patch release. It fixes the ORAS
setup failure that blocked the 0.9.1 Runtime Appliance OCI publish and
normalizes ownership of CI and release toolchain dependencies so the same
class of drift is caught before a release publishes, not during one.

## Release infrastructure fixes

The 0.9.1 publish failed in the "Setup ORAS CLI" step of the Runtime
Appliance OCI publish job: the pinned `oras-project/setup-oras` revision
resolves the ORAS CLI from a version-to-checksum table baked into that
revision, and the requested CLI version postdated the table. `with.version`
is corrected to a version actually present in the pinned revision's table,
and a regression check now fetches that table for whatever revision is
pinned and fails a PR with a clear diagnostic if the requested version isn't
in it, before any release reaches this step again (#821, #822).

## Dependency ownership

CI and release toolchain dependencies across `.github/workflows/**` were
inventoried: external GitHub Action pins, Action-installed tool versions,
and duplicated version literals for the same tool. All external Action pins
were confirmed current and correctly SHA-pinned. A duplicate pnpm-version
literal between `package.json`'s `packageManager` field and a standalone
Review Pages workflow step is now covered by a regression test so the two
can't silently drift apart (#821, #822).

## Distribution

npm publishes the CLI and MCP package as `mottainai@0.9.2`. This release
also completes the Runtime Appliance OCI Artifact publish that 0.9.1 could
not reach.

## Upgrade

Use `mottainai@0.9.2` for the npm surface. No breaking changes to existing
configuration or state schemas are introduced by this release.
