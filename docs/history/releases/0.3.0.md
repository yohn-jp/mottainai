# Mottainai 0.3.0

Mottainai 0.3.0 is the operational Manager dogfood release. It advances the 0.2.0 managed-development milestone into a practical multi-agent control plane with bounded resource scope, Nawabari claim preflight, a four-file operational console, and stricter fail-closed behavior at configuration, Manager request, and search boundaries.

## Highlights

- Manager now previews bounded resource scope before launch and performs Nawabari claim preflight before creating managed work.
- The Manager operational console adopts the four-file UX and exposes the current managed lifecycle without making UI state authoritative.
- Managed process handles are connection-local and bounded by active-count, lifetime, and retained-result limits.
- Nawabari execution ownership is closed only after authoritative integration evidence, preserving recoverable work on ambiguous close paths.
- Managed gh-inari compatibility is capability-gated rather than tied to a stale exact version assumption.

## Reliability hardening

Three release blockers were closed immediately before this release:

- Closed configuration objects reject unknown keys instead of silently accepting misspelled safety/governance settings (#470).
- Manager compatibility aliases and duplicate scope forms reject conflicting values instead of silently widening execution scope (#471).
- ripgrep command, producer, and parser failures are distinct from a genuine zero-match search result, with bounded diagnostics and fail-closed behavior (#472).

## Governance and distribution

- Release governance is pinned to an immutable upstream revision.
- The release continues the packed-package and managed workflow product-contract gates established in 0.2.0.
- Package metadata now describes Mottainai as a coding-agent orchestration and MCP context runtime rather than only an MCP compression proxy.

## Compatibility

Mottainai remains pre-1.0. The managed workflow requires compatible external Nawabari and gh-inari companions and fails closed when their required contracts are unavailable. Existing MCP proxy/compression capabilities remain part of the product.

## Upgrade

After publication, pin MCP client registration to `mottainai@0.3.0`. Existing 0.2.0 users should run `mottainai doctor` after upgrading and verify the managed companions before starting new workflow tasks.

This release contains 11 commits after `v0.2.0`, including #376, #379, #380, #381, #405, #407, #468, #470, #471, and #472 plus organization-managed governance synchronization.
