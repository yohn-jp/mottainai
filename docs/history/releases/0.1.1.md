# mottainai 0.1.1

## Highlights

This release adds workspace initialization: a `mottainai init` command that
writes a portable configuration and verifies the setup. Client registration
is opt-in — pass `--client claude` or `--client codex` to also register the
gateway with your MCP client; the bare command defaults to `--client none`
and does not touch client configuration.

## Added

- **Workspace initialization** (`mottainai init`) — creates a portable v2
  `mottainai.config.json`, supports non-interactive defaults (`--yes`),
  dry-run and JSON output (`--dry-run`, `--json`), personal Git exclusion,
  atomic writes, and backups of any existing config. Client registration
  is opt-in via `--client claude|codex|none` (default `none`); when
  requested, it emits a pinned registration command for Claude Code or
  Codex. After writing the config, `init` runs `doctor` and a stdio MCP
  `initialize`/`tools/list` handshake to confirm the gateway starts
  cleanly.
- **Safe stdio startup** — running the bare `mottainai` command with no
  configuration present now produces a clear initialization hint on stderr
  instead of writing anything to MCP stdout, which is reserved for the
  protocol.

## Migration

No action required for existing workspaces with a working
`mottainai.config.json` — `mottainai init` is additive and only needed for
new workspaces or to pick up the new non-interactive/CI flags.

For a new workspace:

```bash
npx -y mottainai@0.1.1 init
```

For CI or other non-interactive environments:

```bash
npx -y mottainai@0.1.1 init --yes --no-register
```

## Breaking Changes

None.

## Installation

```bash
npx -y mottainai@0.1.1 init
```

Register with your MCP client:

```bash
# Claude Code (user-level registration)
claude mcp add -s user mottainai -- npx -y mottainai@0.1.1

# Codex
codex mcp add mottainai -- npx -y mottainai@0.1.1
```

## Upgrade

```bash
claude mcp remove -s user mottainai
claude mcp add -s user mottainai -- npx -y mottainai@0.1.1
```

Then reconnect your client (`/mcp reconnect mottainai` in Claude Code, or
restart) so it picks up the new version. No config migration needed from
0.1.0.
