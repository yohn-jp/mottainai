# Mottainai 0.8.0

Mottainai 0.8.0 completes the production Lima-managed Runtime distribution path: `mottainai-init` can now bootstrap a managed provider, resolve the canonical Runtime Appliance by immutable GHCR OCI digest, materialize it, and reconcile a QEMU/KVM Runtime through to the canonical guest health boundary. It also hardens Manager/runtime request handling, tightens OCI and Lima control-plane bounds, and reduces CI wall-clock latency.

## Runtime distribution

The canonical Runtime Appliance is built from a bootstrap-only Nix closure (#639) and published as a GHCR OCI artifact using the repository's artifact-type/media-type contract, with a round-trip verified digest as the authoritative identity (#640). `mottainai-init` gained production Lima Runtime orchestration (#664), a complete managed Runtime Nix package catalog (#666), idempotent host bootstrap (#656), and a durable release artifact of its own (#665). Managed generation reconciliation is implemented (#638) and exposed as a production interface (#646), with managed lifecycle state projected through runtime health (#647) and managed generation builds made environment-independent (#645).

## Runtime and Lima hardening

Runtime ensure now serializes safely under a host-bootstrap lock (#686) and a dedicated ensure lock (#675), managed-runtime reconcile transactions are serialized (#688), and Lima YAML configuration is serialized safely (#679, #667). OCI control-plane response bodies are now bounded (#684, #671), decompressed Appliance size is hard-bounded (#682, #668), `limactl` output is drained under a bound (#683, #672), Runtime Appliance OCI metadata is verified before use (#670), and the legacy runtime-ensure surface is retired in favor of the managed path (#674). Incompatible state schemas now fail closed instead of silently degrading (#680, #669), and managed-runtime compatibility defaults are aligned (#681, #676).

## Manager and workflow correctness

Manager session identity is enforced at the service boundary (#696, #454), result retrieval bounds are kept coherent (#697, #402), TAP directives and multiline diagnostics are parsed correctly (#699, #397), await cancellation is distinguished from child-process cancellation (#631, #398), the terminal bridge input race is eliminated (#632, #620), and route-specific 405 responses are returned for unsupported HTTP methods (#623, #403). Inari-owned PR body rules are removed from the workflow surface (#691, #689).

## CI and platform

CI wall-clock latency is reduced across runtime, integration, packaging, and path gating (#701, #694), main-wide concurrency serialization is removed (#693, #692), Node.js 22 support is dropped with Node.js 24 as the runtime floor (#700, #695), and packed workflow fixture cleanup is made deterministic (#698, #690). PR review context is now published as static, deterministic Review Pages (#707). The runtime golden path now boots against deterministic fixtures instead of historical Mottainai/Nawabari releases (#708, #703), and Runtime Appliance delivery through Lima is proved end-to-end (#653, #657, #630, #655).

## Distribution

npm publishes the CLI and MCP package as `mottainai@0.8.0`. The canonical Runtime Appliance for this release is published to GHCR as a separate OCI artifact lifecycle at the exact `v0.8.0` source revision; its immutable manifest digest is the value required by `RuntimeSpec.appliance` and `mottainai-init runtime ensure --spec ...`.

## Upgrade

Use `mottainai@0.8.0` for the npm surface. Existing 0.7.x configuration remains compatible; incompatible state schemas now fail closed rather than degrading silently, and Node.js 24 is required.
