# Mottainai 0.4.0

Mottainai 0.4.0 is the Wabachi interaction-convergence release. It restores the approved two-surface product model and advances the approved Interaction Prototype v2 behavior into the live runtime.

## Wabachi is now the Dashboard

`mottainai dashboard` now serves the approved Wabachi Semantic Investigation Desk rather than a third Semantic Project Viewer surface. The retired `semantic-project-viewer-v2.html` and `semantic-project-viewer-v3.html` assets are removed from source and packed runtime output.

Wabachi remains a read-only semantic investigation surface. Its semantic implementation is still embedded in Mottainai for compatibility in this release; ownership can move into the standalone Wabachi product later without changing the UI/authority contract introduced here.

## Live semantic investigation

The Wabachi v2 interaction model now consumes the existing bounded `/api/v1/*` RepositorySemanticQuery boundary instead of a browser-local fixture dataset. The investigation flow preserves:

- Finding → Impact → Evidence → Relations → Source;
- declared/canonical, observed, derived, analysis/inferred, integrity, and contradictory evidence distinctions;
- bounded entity and graph expansion rather than graph hairballs;
- keyboard navigation and investigation history/context;
- explicit stale, invalid, missing-evidence, and semantic-query failure states;
- provenance refresh without discarding the current investigation.

The browser does not become a second semantic authority. It only projects bounded server responses.

## Mottainai × Wabachi interaction

Both approved v2 context paths are now active.

### Wabachi → Manager

A Wabachi finding can create a Work Intent carrying repository, revision, finding, semantic focus, requested scope, and implementation instruction. These values are presentation intent only. Manager shows them as editable input and runs the authoritative `/sessions/preview` claim preflight before launch. Nawabari remains physical branch/worktree/claim authority.

### Manager → Wabachi

Manager Session Detail exposes `Open semantic context`. It transfers only read-only repository/session/revision context into Wabachi while leaving managed terminal, recovery, and execution actions in Manager. No execution authority is transferred to Wabachi.

## Distribution and regression protection

Build/package wiring now selects `wabachi.html` as the Dashboard root and explicitly removes stale `semantic-project-viewer-v*.html` files from `dist/dashboard` before packaging. Source, HTTP integration, Manager handoff, JavaScript syntax, and packed-consumer tests protect the approved surface from regressing to an unapproved viewer.

## Compatibility

There is no public CLI or RepositorySemanticQuery schema break in this release. Fixture/live providers, loopback serving, explicit Dashboard/Manager ports, Manager execution authority, Nawabari authority, and gh-inari authority remain intact.

The presentation change is intentional: the Semantic Project Viewer variants were not an approved independent product surface and are removed rather than retained as compatibility fallbacks.
