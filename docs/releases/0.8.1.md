# Mottainai 0.8.1

Mottainai 0.8.1 is a patch release that unblocks the v0.8.0 GHCR Runtime Appliance publication (#709), completes the appliance OCI metadata verification contract, and retires the superseded direct-QEMU Runtime surface from the npm CLI.

## Runtime distribution

The v0.8.0 release run's `build` job failed before it could publish the canonical Runtime Appliance: `publish.yml` is the only workflow that runs the fast unit test suite (`ci.yml` only runs `test:integration`), so a pair of `src/bootstrap/cli.test.ts` tests that intentionally write to the real canonical `/var/lib/mottainai-control` path hit their first real-runner execution there and got `EACCES` on the non-root `ubuntu-latest` runner. `publish.yml`'s `build` job now provisions and owns that directory before the test step (#711).

## Appliance OCI metadata verification

`mottainai-init`'s Runtime Appliance resolver now binds the compressed release metadata to the actual compressed layer and its immutable OCI manifest descriptor: `compressedAsset.sha256`/`sizeBytes` are required, validated, and cross-checked against the raw OCI layer descriptor and the downloaded bytes, and the raw layer descriptor `size` is enforced exactly after a bounded download (retaining the existing 8 GiB safety limit and immutable manifest-digest identity) (#685).

## Runtime surface cleanup

The npm CLI's superseded direct-QEMU Runtime lifecycle surface is retired. `runtime ensure`/`runtime status` no longer reach the pre-#600 direct QEMU/QMP/SSH implementation; the CLI fails closed before any legacy Runtime state or artifact access and points to the standalone `mottainai-init runtime ensure --spec PATH` contract. The obsolete `src/local-runtime` implementation, its tests, and the Mottainai-owned QEMU artifact builder/verifier/smoke contracts are deleted; canonical Runtime Appliance and `mottainai-init` Rust orchestration are unaffected (#687).

## Distribution

npm publishes the CLI and MCP package as `mottainai@0.8.1`. The canonical Runtime Appliance for this release is published to GHCR at the exact `v0.8.1` source revision; its immutable manifest digest is the value required by `RuntimeSpec.appliance` and `mottainai-init runtime ensure --spec ...`.

## Upgrade

Use `mottainai@0.8.1` for the npm surface. If you were using the npm CLI's `runtime ensure`/`runtime status` commands directly, switch to `mottainai-init runtime ensure --spec PATH`; the npm CLI now returns deprecation guidance instead.
