# Mottainai 0.5.0

Mottainai 0.5.0 is the managed-workflow and external-discovery release. It turns the post-0.4 Manager/workflow work into a consumable release boundary, including the task/session discovery contract used by Majiwari and other external consumers.

## Cross-workspace task discovery

Mottainai now exposes read-only task/session discovery across registered workspaces. External consumers can use `task list` as a bounded snapshot and resolve a selected task immediately before execution with `task status --task-id <id>`.

This deliberately separates discovery from authority:

- `task list` is a read-only snapshot for selection and presentation;
- `task status --task-id` performs a fresh authoritative resolve before action;
- consumers do not need to read Mottainai or Nawabari internal state directly;
- Nawabari remains physical Git/worktree/session/claim authority.

Majiwari is the first consumer of this contract, but the interface is intentionally generic rather than product-specific.

## Manager and workflow hardening

Manager and the governed workflow path received substantial operational hardening since 0.4.0:

- richer task/session lifecycle handling and reconciliation;
- bounded terminal bridge behavior and session controls;
- improved claim-preflight parity and stale-state handling;
- fail-closed handling for unexpected Manager HTTP failures, with internal exception detail redacted at the HTTP boundary;
- additional packed golden-path and regression coverage around managed execution.

The UI remains a projection over runtime state rather than a second authority.

## Configuration durability

Raw configuration updates now use same-directory atomic replacement. Candidate configuration is validated before filesystem mutation; write/close/rename failures preserve the previous config byte-for-byte; successful replacement leaves no temporary artifact.

Existing destination permission bits are applied to the temporary file before rename, so private configurations such as `0600` do not become more permissive because of umask. Fresh initialization continues to create config with explicit `0600` mode.

## MCP version identity

Upstream MCP initialization now advertises the actual Mottainai package version rather than a stale hard-coded client version. This keeps runtime identity aligned with the package being executed.

## Distribution and verification

The 0.5.0 release path is covered by the repository's release governance and packed-package checks. Publishing verifies tag/package-version equality, builds and tests the package, packs one tarball, smoke-tests that artifact on Node 22 and Node 24, and publishes that same artifact to npm through trusted publishing.

## Compatibility

This is a pre-1.0 minor release. No intentional breaking CLI migration is required from 0.4.0 for the primary `init`, `doctor`, `manager`, MCP stdio, or governed task workflows.

Consumers that need cross-workspace discovery should use the new public task discovery commands rather than reading Mottainai/Nawabari persistence directly.

## Upgrade

After publication, use `mottainai@0.5.0`.
