# Mottainai 0.6.0

Mottainai 0.6.0 is the native harness-delegation MCP release. It promotes Mottainai's governed work lifecycle to a packaged, high-level MCP surface that can be consumed directly by MCP clients or published transparently through gateways such as Majiwari.

## Native harness-delegation MCP

The packaged `mottainai-mcp` executable now exposes the Harness through standard MCP stdio without requiring a source checkout or importing Mottainai internals.

The public surface includes:

- `mottainai_delegate_work` to delegate governed work;
- `mottainai_inspect_work` to inspect bounded lifecycle and evidence state;
- `mottainai_continue_work` to continue an existing opaque work item;
- `mottainai_cancel_work` to request cancellation through Mottainai's lifecycle authority;
- `mottainai_harness_capabilities` to discover the versioned launch, status, and error contract.

Delegation returns an opaque stable `workId`. Follow-up operations use that ID rather than reconstructing repository, worktree, session, or runtime state outside Mottainai.

## Authority boundary

Mottainai remains authoritative for Harness tool schemas, work lifecycle semantics, structured errors, and evidence projection. The native MCP surface is a transport boundary, not a second orchestration implementation.

Nawabari remains authoritative for physical Git/worktree/session/claim state. gh-inari remains the governed GitHub Issue/PR mutation authority. External MCP consumers do not acquire either authority.

## Majiwari publication

The packaged MCP entrypoint is intentionally consumable by generic gateways. Majiwari can launch the installed `mottainai-mcp` command and publish its tool discovery, invocation, result shapes, and structured errors unchanged.

Before this release, the packed 0.6.0 candidate was installed locally and exercised through the Majiwari resident gateway. The native Mottainai MCP was discovered and invoked successfully alongside the existing OCR and Inari adapters. Majiwari remains optional and is not a runtime dependency of Mottainai.

## Existing compression gateway

This release does not remove or replace Mottainai's existing MCP context/compression gateway. The native Harness MCP and the compression gateway are distinct product surfaces: the former exposes Mottainai's own high-level execution capability, while the latter continues to bound and compress upstream MCP context.

## Distribution and verification

The package exports `mottainai-mcp` as an installed binary. Publishing verifies tag/package-version equality, builds and tests the package, packs one tarball, smoke-tests that artifact on Node 22 and Node 24, and publishes the same artifact to npm through trusted publishing.

## Compatibility

This is a pre-1.0 minor release. No intentional migration is required for existing `mottainai`, `mtnai`, Manager, governed task workflow, or compression-gateway users.

Consumers that want the new Harness surface should invoke the packaged `mottainai-mcp` entrypoint directly or through a transparent MCP gateway.

## Upgrade

After publication, use `mottainai@0.6.0`.
