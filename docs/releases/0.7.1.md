# Mottainai 0.7.1

Mottainai 0.7.1 is a patch release focused on making the 0.7.0 runtime and workflow line safer to operate in practice. It restores the Nix package build, modernizes the Nix toolchain, tightens schema-derived MCP validation across the remaining owned tool families, strengthens Manager/workflow identity handling, and adds composed recovery and real-client anti-bypass evidence.

## Runtime and distribution

The Nix package build introduced with 0.7.0 is restored against the tracked repository source. The workspace and fixed-output pnpm store now include the build-time dependency shape required by Nix, while the packaged runtime is reduced back to production dependencies before shipping.

The Nix toolchain is also aligned on Node.js 24 for the supported Runtime build path. CI now evaluates governance and integration shards in parallel to reduce release feedback latency without changing the product contract.

## Schema-derived MCP validation

The reusable schema-derived runtime validator introduced in 0.7.0 is now applied across the remaining Mottainai-owned tool families:

- local execution/read/search/list and broker/catalog tools;
- code-search wrappers;
- workflow task tools;
- adaptive routing tools; and
- proxy-owned request envelopes.

Owned envelopes fail closed before side effects or upstream calls. Repository-governed branch types remain authoritative without advertising an enum that the runtime does not actually enforce. Opaque forwarded argument payloads remain open only at their explicit nested boundary.

## Workflow and Manager correctness

Manager session identifiers now use one canonical Manager UUID contract across HTTP parsing and runtime/Zellij naming boundaries. Malformed UUID-like values are rejected before lookup or process naming.

Contradictory configuration bounds are rejected instead of silently clamped. Individual field validation occurs before cross-field validation so callers receive the most specific bounded diagnostic.

Generated workflow branches can no longer duplicate the linked Issue identity silently. The same invariant is surfaced in Manager preview and enforced before Git/Nawabari mutation.

## Recovery and security evidence

This release adds composed restart evidence for external effects across task start, commit, push, and pull-request creation, and proves validation evidence remains bound to the authoritative task worktree rather than a caller-selected workspace.

Managed-hook enforcement is also exercised with a real Claude Code client. The managed MCP allow path is bound to verified Mottainai registration identity rather than raw tool-name equality, so a same-named foreign MCP tool cannot inherit the managed-capability bypass. Unknown and unverified tools remain on the governed fail-closed path.

## Known follow-up

Issue #620 tracks a separate Manager terminal bridge race where input sent immediately after WebSocket `open` can arrive before PTY message handling is attached. The defect is tracked explicitly rather than hidden behind retries or a larger timeout; it is not introduced by 0.7.1.

## Distribution

npm publishes the CLI and MCP package as `mottainai@0.7.1`. The Runtime
Appliance is a separate GHCR non-container OCI Artifact; its `v0.7.1` tag is a
convenience locator for the exact source revision, while the resolved
`sha256:` descriptor digest is the canonical distribution identity. See
[`docs/runtime-appliance-oci.md`](../runtime-appliance-oci.md) for the pull and
verification flow.

## Upgrade

Use `mottainai@0.7.1` for the npm surface. Existing 0.7.0 configuration remains compatible; malformed or contradictory inputs may now fail earlier and more explicitly.
