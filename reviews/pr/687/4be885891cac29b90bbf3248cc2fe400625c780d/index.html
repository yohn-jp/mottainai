#674 fix(runtime): retire the legacy TypeScript direct-QEMU runtime ensure surface (open)

Acceptance criteria

  • [ ] `mottainai runtime ensure/status` no longer silently routes to the superseded direct managed-QEMU/QMP implementation.
  • [ ] The supported user-facing path is explicit: either the npm CLI safely delegates/discovers the standalone `mottainai-init` contract, or it deprecates/removes the Runtime subcommand and directs users to `mottainai-init`.
  • [ ] No fix resurrects Mottainai-owned QEMU artifact distribution or private QMP lifecycle contrary to #600.
  • [ ] Direct QEMU/KVM users may still consume the canonical Runtime Appliance directly; that provider-independent capability is not coupled to the npm CLI legacy implementation.
  • [ ] Obsolete `src/local-runtime/*` code and QEMU artifact contracts are removed from the reachable production surface and deleted where no retained consumer requires them.
  • [ ] CLI/help/docs/tests describe the same canonical Runtime architecture and do not claim unavailable managed-QEMU artifacts.
  • [ ] A regression test proves the public Runtime command cannot enter the all-`not-built` legacy artifact path.
