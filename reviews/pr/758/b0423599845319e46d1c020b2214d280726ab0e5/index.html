Acceptance criteria

  • [ ] Add a bounded versioned deployment descriptor schema with deterministic canonical identity and strict validation.
  • [ ] Release CI emits one descriptor for the exact tagged release containing all Route 1-4 identities/profile information required by the initial Linux `x86_64` profile.
  • [ ] Route 1 application identity matches the exact canonical payload from #751.
  • [ ] Route 2 managed-generation/Nix inputs in the descriptor resolve the same release lineage and cannot silently target HEAD or another tag.
  • [ ] Runtime Appliance reference uses immutable OCI digest and validates against published canonical Appliance metadata.
  • [ ] `mottainai-init` carries a cryptographic immutable identity sufficient for pre-execution verification.
  • [ ] Lima/QEMU requirements are represented as an explicit supported provider/provisioning profile that can identify and verify the dependency actually selected by Route 4 without declaring Mottainai ownership of its VM lifecycle.
  • [ ] Descriptor generation detects and rejects cross-release/source mismatches among Mottainai-owned referenced artifacts and incompatible provider-profile combinations.
  • [ ] The descriptor is published through a durable versioned public surface and a fresh consumer can retrieve and validate it without repository checkout.
  • [ ] Normal Route 3/4 code can derive the current `RuntimeSpec`/equivalent Appliance identity, initial managed-generation intent, and Route 4 provider requirements from one selected release descriptor, eliminating mandatory manual digest/spec/manifest/provider wiring.
  • [ ] Release workflow no longer encodes a false architectural dependency where the Runtime Appliance must wait for public npm registry publication merely because both belong to one release; exact Route 1 payload identity is sufficient.
  • [ ] Tests cover canonical success, missing identity/profile, mutable-only artifact reference, wrong source revision, wrong architecture/profile, digest mismatch, unknown schema, incompatible Lima/QEMU profile, and historical immutable descriptor retrieval.
  • [ ] Documentation shows the one-release golden path and clearly separates advanced explicit artifact/provider overrides.
