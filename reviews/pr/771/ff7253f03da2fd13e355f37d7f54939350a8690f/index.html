Acceptance criteria

  • [ ] PR Runtime validation is decomposed into explicit Nix Runtime, VM, Appliance, and bootstrap-composition proof boundaries consistent with `docs/ci-topology.md`.
  • [ ] Nix Runtime-only changes do not automatically execute VM or Appliance work unless their dependency graph is actually invalidated.
  • [ ] VM-semantic changes execute the required Runtime build/evaluation prerequisites plus VM validation.
  • [ ] Appliance-defining changes build the canonical Appliance and validate its bounded manifest before merge.
  • [ ] Host-bootstrap-only changes can complete using hermetic/fixed descriptor/manifest/OCI contract fixtures without rebuilding the canonical Nix VM/Appliance.
  • [ ] Shared contract changes select every true dependent validation class.
  • [ ] Stable required-check/ruleset semantics remain deterministic despite internal decomposition/skips.
  • [ ] Failure output identifies the owning contract rather than hiding all failures behind one monolithic Runtime job.
  • [ ] No assertion is removed solely for latency; assertions move only to the proof boundary that owns them.
  • [ ] Representative CI evidence covers a host-bootstrap-only PR, a VM-affecting PR, and an Appliance-affecting PR.
