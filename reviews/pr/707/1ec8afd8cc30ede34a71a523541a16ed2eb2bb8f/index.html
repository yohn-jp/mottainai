#704 feat: publish deterministic PR review context as static Review Pages (open)

Acceptance criteria

  • [ ] A dedicated Review Pages implementation directory exists and contains the schema/generation logic without embedding that logic in the main CI workflow.
  • [ ] A versioned machine-readable review manifest schema is defined and validated.
  • [ ] The generator records PR number, base SHA, head SHA, linked Issue information where available, changed-file/diff metadata, OCR deterministic output, checks/CI evidence, and governance state where available.
  • [ ] Open Code Review output is exported/consumed through a structured interface rather than reimplementing OCR review preparation semantics.
  • [ ] Draft PRs do not produce review-ready published revisions.
  • [ ] `ready_for_review` and later eligible head changes generate a SHA-specific review package.
  • [ ] Each published head-SHA path is immutable and a PR-level index resolves the latest eligible revision.
  • [ ] GitHub Actions publishes the generated package to the repository's GitHub Pages site using standard hosted Actions only; no paid/larger runner dependency is introduced.
  • [ ] A reviewer can obtain the complete canonical review package for a PR revision via plain HTTP without MCP or GitHub Actions artifact APIs.
  • [ ] Publication is safe under concurrent PR updates and does not allow one PR deployment to erase or overwrite another PR's published review data.
  • [ ] Generated/static output excludes unnecessary raw logs and binaries and remains bounded enough for GitHub Pages limits.
  • [ ] Tests prove deterministic generation from fixed fixture inputs and schema validation of the published manifest.
  • [ ] Documentation states the ownership boundary between Open Code Review, Review Pages generation, GitHub Actions publication, and downstream reviewers.
